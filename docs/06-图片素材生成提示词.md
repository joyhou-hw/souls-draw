# 06-图片素材生成提示词（T4.6a 素材管线·外部模型调用手册）

> **用途**：本文档是 T4.6 图片素材管线的第一半——**素材生成提示词 + 存储规划**。供新任务（或操作者）使用外部 AI 图片生成模型（Seedream / TRAE text_to_image / 其它）批量产出罗小黑画风的图层素材库。
>
> **分工**：T4.6a（本文档）= 提示词定义 + 存储规划 + 素材库索引 schema 预告；T4.6b（后续工程任务）= 素材库 schema 落地 + Canvas 纸娃娃合成器实现。两者通过本文档 §5 的文件接口约定衔接。
>
> **设计权威**：01 §4.4（narrative_feed）、§5.5.1（Canvas 客户端合成）、§5.5.3（构建期管线）；03 §6（narrative_feed.image 权威结构）；04 §6 T4.6（降级登记→重启）。

## 一、上下文：新任务须知的全局背景

### 1.1 项目是什么

《生灵引》是一个通用"人生模拟"框架，首个世界包为《罗小黑战记》。引擎用 Node + TypeScript 实现，Web 端为 vanilla TS + Vite 纯静态 SPA。核心铁律：**同 seed 同人生**（确定性）、**游玩期零生成零服务**（纯静态）。

### 1.2 图片素材管线在做什么

游戏中的"里程碑照片"（narrative_feed）是叙事层的第二输出模态：当玩家人生中发生"第一次XXX"类纪念性事件（第一次化形、第一次入会馆、第一次开灵域……）时，除了文本快照，还生成一张**图片快照**。

图片走 **开发期预生成 + 运行时确定性合成**（galgame 纸娃娃式图层拼合）：
- 开发期：用 AI 批量产出罗小黑画风的图层素材（场景底图 + 主角图层 + 同伴图层），存入素材库
- 运行时：根据人生参数（种族×形态×年龄段×服装×姿态）确定性检索图层，Canvas 客户端合成——**游玩期零 AI 生成**

### 1.3 画风锁定（style_lock）

罗小黑画风关键词（所有素材共用）：
- **整体**：东方水墨动画风、温和日常、轻奇幻质感、留白克制
- **线条**：手绘感线条、圆润柔和、无硬边
- **色彩**：低饱和、偏暖灰调、局部点彩（灵质光效用冷色点缀）
- **光影**：柔光、无强烈明暗对比、日式动画光照
- **质感**：水彩晕染 + 少量纸张纹理
- **参考**：《罗小黑战记》TV 番剧 + 大电影画风（MTJJ Studio）

### 1.4 素材库预算（library_budget: ~2000）

来源：03 §6 narrative_feed.image.library_budget。

| 素材类别 | 参数维度 | 数量估算 | 说明 |
|---|---|---|---|
| 场景底图 | 地点 × 时代 | 4 地点 × 2 时代 = 8 | forest / city / guild_land / hermit_island × ancient / modern |
| 主角图层 | 种族×形态×年龄段×服装×姿态 | ~1200–1500 | 详见 §3 枚举参数矩阵 |
| 同伴图层 | 同伴类型 × 姿态 | ~200–300 | 妖精同伴 / 人类同伴 / 师徒组合 |
| 里程碑特效 | 里程碑类型 | ~50–100 | 化形光效 / 灵域展开 / 突破光环 / 飞升等 |
| **合计** | — | **~1800–2000** | 与文本库同量级预算（01 §6.3 起步 1500–3000 条） |

| 路径 | 计费 | 适用场景 | 建议 |
|---|---|---|---|
| Seedream 插件（配火山引擎 API key） | 走火山账户按量，不占 TRAE 套餐 | 大批量生成主力路径 | **推荐**——2000 张规模走外部 API key 最经济 |
| TRAE 内置 text_to_image API | 按张+分辨率扣 TRAE 账号额度（积分） | 少量打样 / 画风校准 | 用于初期 10–20 张打样定风格 |

**建议工作流**：先用 TRAE text_to_image 打样 10–20 张定画风 → 确认 style_lock 提示词 → 切换 Seedream 插件批量生成。

## 三、枚举参数矩阵（actor_params）

来源：03 §6 `actor_params: [race, form, age_band, outfit, pose]` + world.yaml 实际枚举。

### 3.1 参数维度与枚举值

| 参数 | 枚举值 | 来源 |
|---|---|---|
| **race**（种族） | human / animal_yao / plant_yao / fungus_yao / spirit_yao / painted_yao | world.yaml birthForm.weights |
| **form**（形态） | 对 animal_yao: cat, wolf, dog, bull, goat；对 plant_yao: flower, grass, tree；对 fungus_yao: mushroom；对 spirit_yao: wisp；对 painted_yao: paper_creature | world.yaml speciesPrototype |
| **variety**（品种，新增） | cat: orange_cat, black_cat, tabby_cat, calico；wolf: snow_wolf, grey_wolf, black_wolf；…（详见 world.yaml speciesVariety） | world.yaml speciesVariety（engine 品种轴，birth.ts + narrative.ts {variety} 槽位） |
| **age_band**（年龄段） | child / youth / adult / elder | 新增维度——妖精寿长，人类偏短 |
| **outfit**（服装） | plain_robe / guild_uniform / hermit_garb / mortal_clothes / ritual_dress | 新增维度——对应营生/生态位 |
| **pose**（姿态） | standing / walking / sitting / meditating / fighting / resting | 新增维度 |

### 3.2 主角图层组合数估算

- human: 1 种族 × 1 形态 × 4 年龄段 × 5 服装 × 6 姿态 = 120
- animal_yao: 1 × 5 形态 × ~4 品种平均 × 4 年龄段 × 5 服装 × 6 姿态 = 2400（过大，需抽样）
- plant_yao: 1 × 3 × ~3 品种 × 4 × 5 × 6 = 1080（过大，需抽样）
- 其余三类（fungus/spirit/painted）形态少，合计 ~300–500

**总量超 2000 预算 → 需抽样策略**：
1. **高频组合全覆盖**：cat/wolf（动物妖高频）+ flower（植物妖高频）+ human 全覆盖 ≈ 800 张
2. **低频组合抽样**：每个低频形态只生成 child+adult × plain_robe+guild_uniform × standing+meditating = 4 张/形态
3. **缺省回退**：合成器检索不到精确组合时，回退到同 form 的默认图层（age_band=youth, outfit=plain_robe, pose=standing）

### 3.3 场景底图矩阵

### 5.4 与 T4.6b（素材库 schema + Canvas 合成器）的衔接约定

**T4.6a 交付物**（本文档 + 生成的素材文件）：
1. 按 §5.1 目录结构组织的 PNG 素材文件
2. 每张素材附带原始提示词记录（可选：存为同名 .txt 便于追溯）
3. manifest.json 索引文件（按 §5.3 schema 填写）

**T4.6b 接手后**：
1. 读取 manifest.json → 建立素材索引（按参数组合 → 文件路径的查找表）
2. 实现 Canvas 纸娃娃合成器：`composeScene(sceneBase, actorLayer, companionLayer?, effectLayer?) → Canvas`
3. 合成器输入：`{ place, era, race, form, variety?, age_band, outfit, pose, companion?, milestone? }`
4. 合成器输出：合成为单张图片的 Canvas（可导出 PNG / 显示在 DOM）
5. 确定性：同一组参数 → 同一张合成图（无随机性——图层全是预生成的）
6. 缺省回退链：精确组合缺失 → 回退到同 form 默认图层（age_band=youth, outfit=plain_robe, pose=standing）

**接口契约**：
- T4.6a 保证：所有素材 PNG 为透明背景（场景底图除外）、统一画风、文件路径与命名严格符合 §5.2
- T4.6b 保证：合成器只依赖 manifest.json + 文件路径，不硬编码任何素材 ID

## 六、批量生成工作流

### 6.1 打样定风格（10–20 张）

1. 用 TRAE text_to_image API 生成 8 张场景底图 + 4 张主角图层 + 8 张特效
2. 人工校验画风一致性，调整 §4.1 画风锁提示词
3. 确认后冻结 style_lock 提示词，进入批量阶段

### 6.2 批量生成（Seedream 插件）

1. 按枚举参数矩阵分批生成主角图层（建议按 race 分批，每批 ≤ 50 张）
2. 每批生成后人工抽检 10%（style_lock 抽检——剔除画风漂移样本）
3. 生成同伴图层 + 里程碑特效
4. 更新 manifest.json 索引

### 6.3 风险控制（04 §9 R7：画风漂移）

- 每 100 张抽检 10 张，画风偏移率 > 15% 则暂停并重新校准 style_lock
- 保留所有提示词记录，便于追溯偏移来源
- 虚构品种（如 moonveil 月魄花）需额外描述约束，避免模型自行"发挥"
