## 1. 项目定位与演进

### 1.1 演进过程

| 阶段 | 讨论内容 | 结论 |
|---|---|---|
| 起点 | 分析《80亿分之1》（https://1in8b.life/zh-hans/）功能模块 | 输出 13 个功能模块 + 五层架构 |
| 中间 | 评估"能否复刻这个工程（含统计数据）" | UI 可复刻；统计数据工作量大；模拟引擎是黑盒无法精确复刻 |
| 落点 | **目标修正：不做像素级复刻** | 开发一个**通用的"人生模拟"框架**，用来模拟其他世界的人生 |

### 1.2 核心目标（用户原话归纳）

> "我的目标不是像素级复刻这个游戏，而是要开发出同类的框架，然后用来模拟其他的世界。比如罗小黑战记中的世界——在那里的世界中，模拟一些从底层到主角的多个人生。"

三个关键词：

- **通用框架**：引擎与世界设定无关，一套引擎吃任意世界；
- **世界 = 数据**：每个世界是一份"世界包"（World Pack）数据，而非代码；
- **从底层到主角**：批量模拟大量平凡人生，让"主角"作为小概率事件链**自然涌现**，而不是硬编码。

## 2. 参照系：《80亿分之1》产品解析

### 2.1 产品概况

《80亿分之1》是一款基于真实全球统计数据的"人生抽签"模拟器：玩家随机"出生"为全球 80 亿人中的某一个，沿着统计意义上的人生分布走完一生，随时可与 80 亿人的真实命运对比。

### 2.2 十三个功能模块

| # | 模块 | 说明 |
|---|---|---|
| 1 | **出生抽选** | 按各国真实人口权重随机抽出生（国家、性别、家庭经济层）；"同秒出生"锚点（与你在同一秒出生的若干人）。**v0.2 核实注记：同秒出生的其他婴儿为系统按统计概率模拟生成，并非真实玩家**——"并列人生感"来自对照叙事，不来自真实他者 |
| 2 | **人生推进** | 按年龄/阶段逐步推进人生线（出生→童年→教育→工作→婚育→老年） |
| 3 | **暂停提问** | 人生中点暂停，问玩家"你幸福吗"等态度问题，与真实调查数据对比 |
| 4 | **统计数据引擎** | 172 国 × 多维度（教育、收入、健康、婚育、存活率…）真实统计分布驱动 |
| 5 | **死亡结局生成** | 按真实死亡率/死因分布生成死亡时点与死法 |
| 6 | **人生纹理** | 细节性小事件拼图，让每条人生"有血有肉"且不重复 |
| 7 | **存档系统** | 保存/回看已生成的多条人生 |
| 8 | **分享传播** | 一键分享人生卡片（核心增长引擎） |
| 9 | **付费点** | 高级功能/深度模拟付费 |
| 10 | **教学版** | 面向课堂的简化版 |
| 11 | **多语言** | 多语种界面与文案 |
| 12 | **API 开放** | life/simulate/person/lineage/live 等端点（1in8b Engine） |
| 13 | **无障碍** | 可访问性支持 |

### 2.3 五层架构（参照系还原）

```
┌─────────────────────────────────────────────┐
│ 表现层：Web UI（抽签/推进/对比/分享卡片）      │
├─────────────────────────────────────────────┤
│ 交互引擎：出生→推进→抉择→结局 的状态机循环    │
├─────────────────────────────────────────────┤
│ 统计模拟引擎：真实分布抽样 + 概率推演（黑盒）  │
├─────────────────────────────────────────────┤
│ 数据源：172 国多维度统计表（工作量大头）       │
├─────────────────────────────────────────────┤
│ 存储 / 社交 / 商业化：存档、分享、付费        │
└─────────────────────────────────────────────┘
```

### 2.4 核心体验循环

```
抽签出生 → 逐年推进 → 抉择点（改变概率而非确定性分支）
→ 死亡结局 → 与 80 亿人对比 → 分享 → 再抽一次
```

它的"钩子"不在玩法深度，而在**真实感的落差冲击**（"我抽到的这一世 vs 你抽到的这一世"）。

## 3. 复刻可行性评估结论

| 模块 | 复刻难度 | 说明 |
|---|---|---|
| UI / 交互流程 | 低 | 交互循环简单，一周可做出骨架 |
| 统计数据 | 高 | 172 国 × 多维度收集清洗，是工作量大头；精度决定产品灵魂 |
| 模拟引擎 | 无法精确复刻 | 真实抽样逻辑是黑盒，只能"近似重建"（用公开统计表逼近） |

**结论**：像素级复刻既不可能也无必要 → **转向通用框架**。保留其三条灵魂机制，替换掉"地球真实数据"这层皮：

1. **出身不可选**（按真实比例随机抽）；
2. **统计决定大方向，抉择只改变概率**；
3. **"和你同秒出生的人"的并列人生感**。

## 4. 通用框架总体设计

### 4.1 核心思想：数据与引擎分离（World Pack）

> 引擎是"世界无关"的：它只知道"种族、出生轴、事件、抉择、死亡表"这些抽象概念。
> 每个世界 = 一份 **World Pack**（DSL 声明 + 文本库 + 数值表），新世界不需要写一行引擎代码。

```
                    ┌──────────────────────────┐
                    │  表现层（Web UI，世界无关）│
                    └────────────┬─────────────┘
                                 │
                    ┌────────────▼─────────────┐
                    │ 叙事层（文本渲染器）        │  ← 文本变体库（预生成）
                    └────────────┬─────────────┘
                                 │
                    ┌────────────▼─────────────┐
                    │ 模拟引擎层（世界无关）      │  ← tick / 事件 / 抉择 / 死亡
                    └────────────┬─────────────┘
                                 │ 读取
                    ┌────────────▼─────────────┐
                    │ 世界包层（World Pack DSL） │  ← 罗小黑包 / 任意世界包
                    └────────────▲─────────────┘
                                 │ 生成
                    ┌────────────┴─────────────┐
                    │ 世界包生成管线（开发期）    │  ← LLM 批量生成 + 人工校验
                    └──────────────────────────┘
```

### 4.2 三条设计公理

1. **出身不可选**：出生即抽签。种族、地点、时代、天赋全部按世界设定比例随机，玩家无法重抽出身（对应《80亿分之1》最核心的"命运落差感"）。
2. **统计决定大方向，抉择只改变概率**：单次抉择不产生确定性分支树，而是修改后续事件的概率分布（对应"你的努力改变的是概率，不是命运"）。
3. **主角 = 小概率事件链的涌现**：不硬编码任何主角。批量模拟十万条人生时，极低概率的事件链（家园被毁 × 天选天赋 × 关键相遇）自然连成主角轨迹——"千万人中的那一个"。

### 4.3 World Pack DSL（v0.2 示意）

```yaml
world: luoxiaohei_v0.2
tick: year

# ── 出生前置链（问题5：从"生灵阶段"开始模拟）──
pre_birth_chain:                  # 可压缩 3–5 tick，可跳过；全程掷骰，出身不可选
  stages: [shengling, jingling, condense, birth]
  shengling:  {p: 环境灵气浓度}   # 阶段0 生灵凝聚（森林/灵质空间 > 城市）
  jingling:   {fate: [漂泊, 灵偶化, 被吸附, 自然凝形]}  # 阶段1 精灵期（无实体）
  condense:   {prototype: 物种原型抽签}  # 阶段2 凝形（动物/植物/菌类/精灵系/绘兽）
  rare_line:  {reincarnated_soul: {p: 0.001}}  # 稀有支线：转世魂灵（前世记忆）
  human_line: 魂灵 → 投胎（家庭/地点掷骰）→ 出生

# ── 出生形态轴（问题4：人类只是选项之一）──
birth_form:                       # 替代旧 species 轴（人类 99.95% / 妖精 0.05%）
  weights: {human: 0.35, animal_yao: 0.30, plant_yao: 0.15,
            fungus_yao: 0.05, spirit_yao: 0.10, painted_yao: 0.05}   # M2 校准
  species_prototype: {animal: [猫, 狼, 犬, 牛, 鸡, 山羊…], plant: [花, 草, 树…]}
  niche: [村头妖, 会馆杂役, 黑户妖, 编外助理, 蛮力苦力…]   # 浪浪山式小妖生态位
birth_axes:
  - region: [原生森林, 超大城市, 会馆领地, 灵质空间城镇, 离岛, 乡镇]
  - era:    [上古, 战乱年代, 王朝, 现代, 未来]     # 默认 现代(无限418年前后)

# ── 修行入口双闸（问题4：修行概率化，非默认）──
cultivation_gate:
  step1_liqi_manifest: {p: 0.25}   # 闸1：灵力显性（灵系抽签，仅显性者可修行）
  step2_entry_event:   {p: 0.15}   # 闸2：入口事件（师承/会馆招募/隐修机缘）
  both_pass: 成为修行者；否则 = 凡人/平凡妖生

talent:
  lixi:   {御灵: 0.55, 生灵: 0.20, 锁御: 0.10, 心灵: 0.07, 造物: 0.07, 空间: 0.01}
  dual_liquality: {p: 0.001}                     # 双灵质空间（小黑、玄离）
  space_lixi:    {acquired: false}               # 空间系不可后天习得（=火影"血继限界"式硬门槛）
  env_modifier:                                  # 环境软修正（非硬绑定）
    原生森林: {木系权重×1.5}
death_rule:
  space_lixi_lost: 灵质空间衰竭                  # 失去空间系能力 → 死亡
death_model: liquality_balance                   # 灵质收支表（见 §7.3）
choice_axes: [cultivation, livelihood, bond, home, spirit_care, stance]
grain_axes:  [扎根↔流浪, 亲人↔避世, 守序↔激进, 共存↔独存]

# ── 场景模板库（问题3确认：种族/习俗/职业/功法/相遇/冲突六维模板）──
scene_templates: scenes/*.yaml    # 每模板 = 触发条件轴组合 × 事件池 × 叙事桶标签
era_shockwaves: shocks/*.yaml    # 时代级冲击波池（战争/改朝/制度/开发/大战，对应80亿分之1的灾害/危机/战争）
events:     events/*.yaml
narratives: narratives/*.yaml                     # 文本变体库（见 §6）
```

> **v0.3 增量预告**（详见 [03-世界观对比与合并方案.md](./03-世界观对比与合并方案.md) §6）：`power_ladder`（灵力阶梯6档+突破事件）、`hard_thresholds`（硬门槛分级：T1 子能力互不可学 / T2 空间系死亡绑定 / T3 双灵质独二档 + 多系上限）、`org_affiliation`（组织光谱六类：会馆籍/黑户/师承线/隐修网络/民间互助会/行业行会/王朝供奉残留，后五类可设人类社会分部）、`entry_event_age_window`（修行入口年龄窗）、`spirit_density`（灵气浓度地标）、`narrative_feed`（里程碑照片：纪念性事件"第一次XXX"触发文本+图片双模态快照——旅行青蛙照片寄送机制，render_only；图片走开发期预生成素材库+运行时确定性合成，玩家=被模拟者本人，无外部资源注入）。

### 4.4 引擎核心概念

| 概念 | 说明 |
|---|---|
| `tick` | 时间步进单位（罗小黑世界为"年"） |
| `event` | 由世界包声明条件与权重的事件，引擎按概率掷骰 |
| `choice` | 玩家在叙事节点上做的抉择 → 修改后续概率字段，不写死分支 |
| `death_check` | 每个回合按死亡模型（生命表/灵质收支表）判定 |
| `batch_sim` | 无 UI 的批量模拟（十万条人生并跑，用于统计与"主角涌现"验证） |
| `narrative_feed` | 里程碑照片：纪念性事件（"第一次XXX"）触发文本+图片双模态快照；零机制负载；图片走**开发期预生成素材库+运行时确定性合成**（v0.3 增量，源自旅行青蛙照片寄送；玩家=被模拟者本人，无外部资源注入，干预仅剩 `choice`） |

## 5. LLM 架构定位

### 5.1 结论（本次讨论最重要的架构决策）

> **游玩路径上没有 LLM。**
> 玩家体验时 = **预生成文本库 + 运行时概率选择**；LLM 只在**开发期**（世界包生成管线）使用。

### 5.2 运行时数据流

```
引擎 tick（掷骰，纯确定性概率）
   → 事件/抉择已定（结构化结果）
   → 叙事渲染器：拿事件类型 + 上下文（种族/地点/年龄/前情标签）
   → 在文本库中按条件桶检索 + 不放回抽样，挑出一条叙事文本
   → 玩家看到"为你这一世写的那句话"
```

### 5.3 LLM 的正确位置

| 阶段 | 用 LLM | 不用 LLM |
|---|---|---|
| 开发期 | 批量生成文本变体（每事件 20–50 个变体）；DSL 草稿；翻译 | — |
| 校验期 | 人工 + 规则过滤（去重、风格、设定一致性） | — |
| **游玩期** | — | **概率引擎掷骰 + 文本库挑选，全程确定性** |

### 5.4 为什么运行时不用 LLM

1. **确定性**：同一条人生可以复现（存档/回放/统计对比要求）；
2. **成本与延迟**：十万条批量模拟若走 LLM，成本与耗时不可接受；
3. **风格一致性**：预生成库经人工校验，文风与设定统一，LLM 实时生成易漂移；
4. **世界观纪律**：设定硬约束（如"空间系不可后天习得"）在预生成时已保证，运行时不会违规。

### 5.5 运行载体与技术栈：纯静态页面可行性裁决（v0.3 增量）

> 触发问题（2026-11-19）："这个游戏的开发框架是什么？用纯静态页面可以实现吗？"
>
> **结论先行：核心玩法 100% 可以用纯静态页面（零后端）承载。**这不是妥协，而是 §5.1–§5.4 架构裁决的自然推论——把 LLM 赶出游玩路径的同时，所有服务端依赖也被一并赶出了核心玩法。另注：本作**不需要 Unity/Godot 类游戏引擎**——没有实时渲染、物理、输入循环，本质是"概率计算 + 叙事检索 + 状态 UI"的信息应用，Web 前端技术栈即全部所需。

#### 5.5.1 逐功能映射：运行时到底需要什么

| 功能 | 运行时形态 | 纯静态承载方式 |
|---|---|---|
| `tick` 引擎（掷骰/事件池/死亡检定） | 纯计算，零 IO | TS/JS 实现，seed 驱动可复现（§5.4 第 1 条确定性的直接背书） |
| 世界包 DSL（world.yaml） | 数据文件 | 构建期编译为 JSON，静态 fetch 加载 |
| 文本库（narratives/*.yaml） | 数据文件 | 同上——文本库本就是"预生成+静态检索"（§5.2），与服务端无关 |
| 里程碑照片（§4.4 `narrative_feed`） | 素材检索 + 图层合成 | 素材库为静态图片文件；Canvas/CSS 客户端合成（galgame 纸娃娃逻辑本就按客户端合成设计） |
| 存档 / 抽签种子 | 本地状态 | localStorage 常驻 + 导出/导入 JSON 文件（换设备可携带） |
| `batch_sim`（十万条无 UI） | 纯计算，零 IO | Web Worker 后台跑 + 进度条 + 涌现统计看板（M4 需求全部落在客户端） |
| 分享 | 文本/图片产物 | 客户端生成分享文案/图片，零上传 |

**判读**：运行时 = 纯计算 + 静态数据检索两项，没有一项需要服务器。§5.4 的四条理由（可复现/成本/风格/纪律）每一条同时是纯静态可行的论据——**运行时零生成 ⇔ 运行时零服务**。

#### 5.5.2 唯一需要服务端的场景（边界划清）

**陌生人社交聚合**：全球排行榜、热门人生流、玩家评论/点赞——需要一个共享数据池，静态页面给不了。裁决：

- 它**不是核心玩法**：核心循环（抽签→推进→抉择→结局→相册回顾）没有它完全自洽；
- **M1–M5 均不含服务端**；社交层若未来启动，作为**独立附加层**单独立项（第三方 BaaS、或静态托管+边缘函数），**不进入引擎与数据管线**；
- 站内"分享"先走文件化：一条人生 = 种子 + 抉择记录，导出为 JSON/文本/图片，与存档格式同构。

#### 5.5.3 技术栈选型

| 里程碑 | 载体 | 选型 | 理由 |
|---|---|---|---|
| M1 引擎 MVP | 命令行 | **Node + TypeScript** | 与 M3/M4 Web 端共享同一份引擎代码（一套实现，两端复用）；备选 Python（若团队更熟），代价是 M4 前需移植 |
| M3 叙事层 | 命令行→Web 过渡 | 同 M1 | 文本库管线是数据工程，先在 Node 侧打通 |
| M4 Web UI | 浏览器 | **vanilla TS + Vite 纯静态 SPA** | UI 状态简单（单人生线性推进 + 批量看板两屏），重框架（React/Vue 全家桶）收益有限；求开发效率可选 Svelte/Vue 轻量方案——**裁决不变：构建产物必须是纯静态文件包** |
| 部署 | — | **GitHub Pages / 任意静态托管** | 零后端 = 零运维、零服务器成本、天然抗并发（没有服务器就没有宕机） |
| 构建期管线 | Node 工具链 | YAML→JSON 编译、素材库索引、（开发期）文本/图片批量生成脚本 | 全是"开发期的活"，与运行时无关（§5.3 LLM 位置表的同构延伸） |

#### 5.5.4 零后端不是省事，是能力

1. **确定性铁律的副产品**：seed 复现要求（§5.4 第 1 条）天然排除服务端状态——状态在服务器上的游戏无法保证"同一条人生可复现"；
2. **十万条 batch 在浏览器里跑**：单条人生模拟为毫秒级纯计算，十万条分钟级，Web Worker 承载无压力；
3. **分享即文件**：存档 = 种子 + 抉择序号，分享退化为"把这个文件给别人"，传播零服务端依赖；
4. **部署即发布**：静态文件包拖到任意静态托管即上线，版本迭代 = 重新上传一次文件夹。

## 6. 文案量估算

### 6.1 Fermi 估算（《80亿分之1》量级参照）

- 一条人生 ≈ **100–150 个叙事节点**（年推进 + 关键事件 + 抉择点 + 结局）；
- 要让玩家连续玩 N 条不感到重复，按"生日悖论"式撞车率反推：单语言核心文案 ≈ **4,000–8,000 条**，上限 1.5–2 万条（含长尾变体）；
- 该数字与原作多语言、多版本的表现吻合（量级验证通过）。

### 6.2 四板斧（压缩文案量的工程手段）

| 手段 | 做法 | 效果 |
|---|---|---|
| 槽位模板化 | "在{place}，你遇到了{person}，{event}" | 一条模板 = 数百条表象文案 |
| 条件桶隔离 | 种族/地点/时代各自成桶 | 同文案在别的桶里可安全复用 |
| 不放回抽样 | 单条人生内已出现的变体不再出现 | 重复感大降 |
| 碎片拼接 | 开头句 + 事件句 + 结尾句自由组合 | 乘法扩容 |

### 6.3 罗小黑世界包文案预算

- **起步（v0，可玩）**：**1,500–3,000 条**（六类地点 × 六条抉择轴 × 主要事件类型）；
- 与四板斧配合，玩家连续模拟 50–100 条人生不出现明显重复；
- 后续按事件类型（战争、会馆任务、灵质危机、人妖冲突…）滚动扩充。

## 7. 罗小黑世界包设计映射

> 世界观设定细节见配套文档《02-罗小黑战记世界观资料集.md》，此处只列"如何映射进模拟框架"。

### 7.1 出生轴（出身不可选）—— v0.2 修正

> 修正缘由（2026-11-19 讨论，问题 4/5）：
> ① 人类不再以 99.95% 压倒性权重占满抽签，**降为"形态轴选项之一"**；
> ② 妖精按物种细分（动物/植物/菌类/精灵系/绘兽），并引入浪浪山式**小妖生态位**；
> ③ **修行入口概率化**：出生 ≠ 修行者，需"灵力显性 + 入口事件"两道掷骰（双闸模型）；
> ④ 新增**出生前置链**：模拟可前置到"生灵凝聚"阶段（见 §7.7）。

| 轴 | 取值（v0.2） | 备注 |
|---|---|---|
| **形态** | 人类 / 动物妖 / 植物妖 / 菌妖 / 精灵系妖 / 绘兽 | 人类仅占一项；权重 M2 校准（演示值见 §4.3） |
| **物种原型** | 猫·狼·犬·牛·鸡·山羊…（动物）；花·草·树…（植物）等 | 决定妖形、凝聚时长、生态位 |
| **小妖生态位** | 村头妖 / 会馆杂役 / 黑户妖 / 编外助理 / 蛮力苦力… | 浪浪山式小人物槽位（资料集 §3.8） |
| 地点 | 原生森林 / 超大城市 / 会馆领地 / 灵质空间城镇 / 离岛 / 乡镇 | 同 v0，各带事件池与环境天赋修正 |
| 时代 | 上古 / 战乱年代 / 王朝 / 现代 / 未来 | 默认"现代"（无限纪年 418 年前后） |
| 天赋（显性） | 独立抽签：御灵 0.55 / 生灵 0.20 / 锁御 0.10 / 心灵 0.07 / 造物 0.07 / **空间 0.01** | **能力与种族无硬绑定**，环境软修正 |

#### 7.1.1 修行入口双闸模型（问题 4 核心修正）

```
出生（任意形态）
  → 闸1：灵力显性掷骰（p1）
       未显性 → 凡人/平凡妖生（小人物人生线，主流）
  → 闸2：入口事件掷骰（p2）
       师承线（小黑遇无限）/ 会馆招募线（无限被王朝征召）/ 隐修机缘线（老君门徒式）
       无入口 → 显性而不修行者（埋没天才事件线）
  → 两闸皆过 → 成为修行者（人生中的"成就"，而非默认）
```

- 对应原作锚点：无限（人类 × 入口线 = 王朝征召 → 最强执行者）、小黑（空间系 × 遇无限）、老君门徒线（清凝/玄离）；
- 效果：**修行者成为小概率成就**，"多数人生平凡"与《80亿分之1》的质感对齐；同时保留"显性而无入口"的埋没天才叙事位。

### 7.2 六条抉择轴（替代"结婚/工作/生子"）

| 轴 | 对应原作母题 |
|---|---|
| 修行轴（拜师） | 小黑拜无限；老君收清凝/玄离 |
| 生计轴（执行者等职业） | 会馆执行者/馆长/隐修 |
| 羁绊轴 | 妖精无血脉繁衍 → "羁绊"合并爱情与亲属的模拟位 |
| **家园轴** | **世界第一主题**：风息失去森林、小黑的"找家"之旅、蓝溪镇的存在本身 |
| 灵质救治轴 | 治愈系稀有性（世间仅数名） |
| 人妖立场轴 | 罗小黑独有轴：共存/隔离/敌对（灵遥 vs 雨笛 vs 风息的光谱） |

### 7.3 死亡与终点体系

**死亡引擎：灵质收支表替代年龄生命表**

```
灵质余额 = 初始灵质
  + 流入：修行增长 / 闭关 / 滋养环境（森林/灵质空间）
  - 流出：战斗损耗 / 被夺（风息式夺灵）/ 心境损耗（漂泊无家）
余额 ≤ 0  → 灵质衰竭 → 真死亡 或 散灵化树
```

**四层终点体系**（详见资料集 §8）：

| 层 | 终点 | 原作案例 |
|---|---|---|
| 真死亡 | 灵质衰竭 / 被夺 / 阵亡 / 战争 / 凡人病老 | 大松（遇袭身亡） |
| 转化 | **散灵化树**（自毁生出擎天大树） | 风息；若木武器造成的散灵 |
| 离开 | 飞升离陆（成仙/成神离场） | 玄离、无限成仙；闫明居冥界 |
| 截断 | 仍在世，人生线暂告一段落 | 模拟默认出口 |

### 7.4 粒度轴（人生气质的连续谱）

扎根↔流浪 / 亲人↔避世 / 守序↔激进 / 共存↔独存
——同一出身上叠加不同气质，走出完全不同的妖生。

### 7.5 主角涌现机制（小黑轨迹分解）

小黑 = 以下低概率事件的**连乘**：

```
家园被毁(p≈0.05/森林出身)
× 空间系天赋(p≈0.01)
× 双灵质空间(p≈0.001)
× 遇见无限而非风息先夺其能力(关键相遇)
× ……
```

批量模拟十万条，只有极少数人生能把这些事件全部串起来——**那一条就是"罗小黑"**。引擎不需要、也不应该知道谁是小黑。同秒出生的另外三个婴儿（风息、洛竹、虚淮）则是"同一起点、不同概率路径"的并列人生展示位——直接对应《80亿分之1》的"同秒出生"模块。

**v0.2 补充（问题 1 结论）**：《80亿分之1》的同秒四婴儿已被核实为**系统按统计概率模拟生成，并非真实玩家**（GameLook 报道原文："系统会按同样的统计概率，在地球另外四个角落生成四个与你同秒出生的婴儿"）。因此本框架的"同秒并列人生"完全用引擎实现：同一出生种子 → 复制四份 → 各自独立掷骰路径 → 四条人生对照展示。无需任何多人机制。

### 7.6 场景模板库（问题 3 确认，v0.2 新增）

**裁决：种族、习俗、职业大类、功法、相遇场景、冲突类型这六维 = 模拟场景的模板框架**，即 World Pack 的 `scene_templates/*.yaml`：

| 模板维 | 取值来源（资料集） | 引擎用法 |
|---|---|---|
| 种族 | 人类 / 妖精（§3） | 触发条件轴 |
| 物种 | 动物/植物/菌类/精灵系/绘兽（§3.6） | 触发条件轴 + 妖形/凝聚时长 |
| 习俗 | 凝形日 / 会馆籍 / 人前不现原形（§3.7，含推定） | 事件池标签（节日/礼俗事件） |
| 职业大类 | 馆长/执行者/长老/隐修/反人类者 + 小妖生态位（§5.2、§3.8） | 生计轴取值 + 职场事件池 |
| 功法 | 七灵系（§4.1） | 天赋轴 + 能力事件池 |
| 相遇场景 | 森林初遇/雨夜收养/会馆招募/离岛群居/师徒滞留/网游结缘…（§9.7） | 关键相遇事件池 |
| 冲突类型 | 家园丧失/能力被夺/立场对立/误会追捕/职场压迫/领地资源/恋慕执念（§9.7） | 冲突事件池 |

一个场景模板 = `触发条件（种族×物种×职业×地点×纪年）× 事件池 × 叙事桶标签`——引擎按人物属性命中模板，掷骰选事件，再从叙事桶抽文本。

### 7.7 出生前置链：从"生灵阶段"开始模拟（问题 5 设计，v0.2 新增）

官方依据（资料集 §3.5）：灵 = 生灵 + 物质灵；生灵自汇聚 → 精灵 → 精灵+物质灵 → 妖精；人类 = 魂灵投胎；极少数强大魂灵凝而不散 → **转世**（保有前世意识）。

```
前置链（妖精线）：
  阶段0 生灵凝聚  ——环境灵气浓度决定汇聚概率（森林/灵质空间 > 城市）
  阶段1 精灵漂泊  ——无实体；去向掷骰：漂泊 / 被收作灵偶 / 被强大妖精吸附 / 自然凝形
  阶段2 凝形     ——物种原型掷骰（动物/植物/菌类/精灵系/绘兽）+ 物质灵结合
  阶段3 出生     ——进入主人生线（灵力显性掷骰 → 双闸）

前置链（人类线）：魂灵 → 投胎（家庭/地点掷骰）→ 出生

稀有支线：转世魂灵（p≈0.001）——前世记忆/羁绊残留事件链
```

- **公理兼容**：前置链全程掷骰，仍然"出身不可选"——你连自己凝聚于哪片森林都无法挑选；
- **叙事价值**："出生前史"成为人生的第一页（你先在林间漂泊了三十年才凝出猫形）；
- **工程价值**：可压缩为 3–5 个 tick 快速跳过，也可展开玩（"精灵漂泊期"本身可成为玩法）；与"聚灵点"事件（灵气充盈处偶发新妖）共用同一套概率表；
- **模板扩展**：转世支线为长线模拟提供跨代叙事钩子（前世今生羁绊）。
